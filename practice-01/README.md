## 4. Задание 1. Один файл — две среды выполнения

Файл `practice-01/js/hello.js` запущен в двух средах. Вывод в терминале Node.js и в консоли браузера совпадает, кроме последней строки.

| Строка вывода                      | Node.js     | Браузер (Console) |
| ---------------------------------- | ----------- | ----------------- |
| `Студент: Данков Степан Андреевич` | 1           | 1                 |
| `Группа: ЭФБО-14-25`               | 1           | 1                 |
| `Практическая работа: 1`           | 1           | 1                 |
| `JavaScript успешно запущен`       | 1           | 1                 |
| `Тип document: ...`                | `undefined` | `object`          |

**Объяснение различия.** `document` — это объект браузерной среды (DOM), а не часть языка JavaScript. Node.js не создаёт HTML-страницу и не предоставляет DOM. Поэтому переменная `document` в Node.js не определена, и оператор `typeof` для неё возвращает `"undefined"`. В браузере эта же переменная ссылается на корневой элемент документа, поэтому `typeof document` даёт `"object"`.

Вывод программы в обоих случаях находится **в консоли**, а не на HTML-странице. Атрибут `defer` в теге `<script>` откладывает выполнение до завершения разбора HTML, но не меняет того факта, что результат появляется в Console.

## 5. Задание 2. Типы данных и преобразования

Для каждого выражения сначала сформулировано предсказание, затем результат проверен через `console.log()` в `types.js`.

|   № | Выражение          | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение                                                                                                                                                               |
| --: | ------------------ | ------------------- | -------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
|   1 | `"8" + 2`          | `"82"`              | `"82"`               | `string`       | Оператор `+` при наличии хотя бы одной строки выполняет конкатенацию: число `2` неявно превращается в строку `"2"`.                                                      |
|   2 | `"8" - 2`          | `6`                 | `6`                  | `number`       | Оператор `-` определён только для чисел, поэтому строка `"8"` преобразуется в число `8`.                                                                                 |
|   3 | `Number("8") + 2`  | `10`                | `10`                 | `number`       | Явное преобразование через `Number()`, затем арифметика.                                                                                                                 |
|   4 | `"12" > "3"`       | `false`             | `false`              | `boolean`      | Оба операнда — строки, поэтому сравнение лексикографическое: `"1"` меньше `"3"` по коду символа.                                                                         |
|   5 | `12 === "12"`      | `false`             | `false`              | `boolean`      | Строгое равенство не преобразует типы. `number` не равен `string`, даже если запись выглядит одинаково.                                                                  |
|   6 | `Number("")`       | `0`                 | `0`                  | `number`       | Пустая строка приводится к нулю. Именно поэтому одной `Number()` недостаточно для проверки корректности ввода.                                                           |
|   7 | `Number("text")`   | `NaN`               | `NaN`                | `number`       | Строка не является числовым значением, но результат относится к типу `number` (специальное значение `NaN`).                                                              |
|   8 | `Boolean("false")` | `true`              | `true`               | `boolean`      | Любая непустая строка истинна. Содержимое `"false"` как текст не анализируется.                                                                                          |
|   9 | `typeof null`      | `"object"`          | `"object"`           | `string`       | Историческая особенность JavaScript: `null` — примитив, но `typeof` для него даёт `"object"`. Сам результат выражения `typeof null` — строка, поэтому её тип `"string"`. |
|  10 | `typeof NaN`       | `"number"`          | `"number"`           | `string`       | `NaN` — специальное числовое значение, поэтому `typeof` даёт `"number"`. Тип самого результата `typeof NaN` — строка `"string"`.                                         |

**Особо отмечу три случая:**

- **Объединение строки с числом.** Оператор `+` работает по-разному в зависимости от типов операндов. Если хотя бы один из них — строка, выполняется конкатенация, а не арифметика.
- **Преобразование пустой строки.** `Number("")` даёт `0`, а `Number("   ")` тоже даёт `0`. Это значит, что одна проверка «получилось число» не отличит корректный ввод `0` от пустого.
- **Логическое преобразование непустой строки.** `Boolean("false")` возвращает `true`, потому что важна не длина и не текст, а сам факт того, что строка непустая.

## 7. Задание 4. План выполнения задач по дням

Файл: `practice-01/js/plan.js`. Данные варианта 2 — `totalTasks = 15`, `completedTasks = 0`, `dailyLimit = 4`.

**Вывод для варианта 2:**

```text
Осталось задач: 15
День 1: выполнено 4, осталось 11
День 2: выполнено 4, осталось 7
День 3: выполнено 4, осталось 3
День 4: выполнено 3, осталось 0
Потребуется дней: 4
```

Последняя итерация отличается от предыдущих: за день выполняется не `dailyLimit`, а остаток. Это обеспечивается через `Math.min(dailyLimit, remaining)` — на четвёртом дне выбирается меньшее из `4` и `3`.

**Таблица обязательных проверок:**

|   № | `totalTasks` | `completedTasks` | `dailyLimit` | Ожидаемое поведение                    | Фактический результат                                                | Итог     |
| --: | -----------: | ---------------: | -----------: | -------------------------------------- | -------------------------------------------------------------------- | -------- |
|   1 |           12 |                5 |            3 | 3 дня; в последний день 1 задача       | 3 дня; день 3 — 1 задача                                             | Пройдено |
|   2 |           10 |                4 |            3 | 2 дня по 3 задачи                      | 2 дня по 3 задачи                                                    | Пройдено |
|   3 |            5 |                3 |           10 | 1 день; 2 оставшиеся задачи            | 1 день; 2 задачи                                                     | Пройдено |
|   4 |            5 |                5 |            2 | 0 дней; цикл не выполняется            | 0 дней; цикл не выполняется                                          | Пройдено |
|   5 |            0 |                0 |            2 | 0 дней; цикл не выполняется            | 0 дней; цикл не выполняется                                          | Пройдено |
|   6 |            5 |                2 |            0 | Ошибка; цикл не запускается            | `Ошибка: dailyLimit должно быть целым числом от 1 до 1000`           | Пройдено |
|   7 |            5 |                2 |          1.5 | Ошибка: дробная норма                  | `Ошибка: dailyLimit должно быть целым числом от 1 до 1000`           | Пройдено |
|   8 |            5 |                6 |            2 | Ошибка: некорректное число выполненных | `Ошибка: completedTasks должно быть целым числом от 0 до totalTasks` | Пройдено |
|   9 |            5 |                2 |        `"2"` | Ошибка: норма задана строкой           | `Ошибка: dailyLimit должно быть целым числом от 1 до 1000`           | Пройдено |
|  10 |            5 |                2 |         1001 | Ошибка: превышена верхняя граница      | `Ошибка: dailyLimit должно быть целым числом от 1 до 1000`           | Пройдено |

**Что обеспечивает корректность цикла:**

- остаток уменьшается на каждой итерации, поэтому цикл заканчивается;
- `dailyLimit >= 1` — без этой проверки возможен бесконечный цикл;
- `Math.min(dailyLimit, remaining)` — остаток никогда не становится отрицательным;
- для случая «все задачи выполнены» цикл не запускается вовсе, выводится `Потребуется дней: 0`.

## 8. Задание 5. Отладка через DevTools

Файл: `practice-01/js/debug.js`. Намеренные ошибки: конкатенация строк вместо арифметики и неверная граница цикла.

**Исходный (ошибочный) вывод:**

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

**Исправленный вывод:**

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

**Порядок отладки:**

1. Сохранил исходный вариант и записал его фактический вывод.
2. Подключил `./js/debug.js` в `index.html`, открыл DevTools → вкладка **Sources / Источники**.
3. Открыл `debug.js`, поставил точку останова на строке вычисления `completedTotal`.
4. Перезагрузил страницу. В панели **Scope** увидел, что `completedText` и `additionalText` имеют тип `string` и значения `"3"` и `"2"`.
5. Нажал **Step over**. Убедился, что `completedTotal` равно `"32"` — результат конкатенации, а не сложения.
6. Поставил точку останова внутри цикла. Проследил, что `taskNumber` принимает значения `1, 2, 3`, но не `4`.
7. Исправил обе ошибки.
8. Повторно запустил в браузере и в Node.js. Удалил активные точки останова.

**Таблица ошибок:**

| Ошибка                     | Что наблюдалось                                 | Причина                                                                  | Исправление                                                                                    | Результат после исправления                |
| -------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Обработка количества задач | `completedTotal = "32"`, `remainingTasks = -24` | Оператор `+` со строками выполнил конкатенацию, а `"8" - "32"` дал `-24` | Явное преобразование: `Number(completedText) + Number(additionalText)` и `Number(plannedText)` | `completedTotal = 5`, `remainingTasks = 3` |
| Граница цикла              | `controlSum = 6` (сумма 1+2+3)                  | Условие `taskNumber < 4` исключает число 4                               | Заменил на `taskNumber <= 4`                                                                   | `controlSum = 10`                          |

**Иллюстрация точки останова:**

![Точка останова в debug.js](./screenshots/debug-breakpoint.png)

На скриншоте видна строка вычисления `completedTotal`, точка останова слева от номера строки и в панели Scope — значения `completedText = "3"` и `additionalText = "2"` с типом `string`.

**Исправленный код:**

```js
const plannedTasks = Number(plannedText);
const completedTotal = Number(completedText) + Number(additionalText);
const remainingTasks = plannedTasks - completedTotal;

// ...

for (let taskNumber = 1; taskNumber <= 4; taskNumber += 1) {
  controlSum += taskNumber;
}
```

Вычисления не заменены константами `5`, `3`, `10` — они по-прежнему зависят от исходных значений `"8"`, `"3"`, `"2"`.

## 9. Вывод

В ходе работы освоены:

- запуск JavaScript в двух средах — Node.js и браузере — и понимание разницы между ними;
- различие `const` и `let`, область видимости и правила переприсваивания;
- типы данных `number`, `string`, `boolean`, `undefined`, `null` и особенности `typeof null` и `typeof NaN`;
- явное преобразование через `Number()` и `Boolean()`, строгое сравнение `===`;
- проверки `Number.isFinite()` и `Number.isInteger()` для валидации числового ввода;
- условия `if` / `else if` / `else` и логические операторы `&&`, `||`;
- циклы `for` и `while`, включая защиту от бесконечного цикла и корректную последнюю итерацию;
- шаблонные строки и `toFixed(1)` для форматирования процента;
- отладка в DevTools через точки останова, пошаговое выполнение и панель Scope.

**Наиболее показательная ошибка** — конкатенация строк в `debug.js`. Выражение `"3" + "2"` даёт `"32"`, а не `5`. Поскольку JavaScript не выдаёт исключение и программа продолжает работать, ошибку можно обнаружить только через точку останова или сравнение типов. Именно поэтому проверять типы входных данных нужно явно — через `Number.isFinite()` и `Number.isInteger()`, а не полагаться на «выглядит как число».

**Вторая полезная ошибка** — граница цикла `taskNumber < 4`. Такая ошибка не приводит к падению и часто остаётся незамеченной без ручной проверки суммы. Она показывает, что даже корректно работающая программа может давать неверный результат.
