## Организация кода

| Модуль              | Ответственность                                                                                            |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| `task-service.js`   | Функции ПР2: создание, поиск, сводка, изменение статуса, удаление. Без DOM и глобального состояния.        |
| `task-selectors.js` | `getVisibleTasks` — отбор по фильтру без изменения исходного массива.                                      |
| `task-view.js`      | Создание карточки, замена списка, обновление сводки и пустого состояния. Без обработчиков.                 |
| `main.js`           | Текущее состояние (`currentTasks`, `currentFilter`), делегированные обработчики и согласованная отрисовка. |

Полный список живёт в `currentTasks`, режим отображения — в `currentFilter`. Событие обрабатывается один раз на контейнере через `closest`. Сводка всегда считается по `currentTasks`, а не по видимой выборке.

## Отладка и клавиатура

**Точка останова:** в `handleTaskListClick` на строке `const id = Number(card.dataset.taskId);`.

Проверенные значения при клике по `toggle` карточки `id = 4`:

| Значение              | До преобразования                    | После преобразования |
| --------------------- | ------------------------------------ | -------------------- |
| `card.dataset.taskId` | `"4"` (string)                       | —                    |
| `id`                  | —                                    | `4` (number)         |
| `action`              | `"toggle"`                           | `"toggle"`           |
| `found.completed`     | `false`                              | `false`              |
| Результат сервиса     | `{ ok: true, tasks: [...4 задачи] }` | —                    |

Проверен отказ: временно изменённое `data-task-id` на `777` даёт сообщение «Задача с id = 777 не найдена.» и не изменяет данные. Значение `4abc` даёт `Number("4abc") = NaN` → сообщение «Некорректный идентификатор задачи.».

**Клавиатура:** кнопки фильтров и действий карточек активируются через `Tab` + `Enter` или `Space`. После `toggle` фокус остаётся на той же кнопке той же задачи. После удаления карточки фокус переходит на активный фильтр.

## Вывод

Освоены выбор элементов через `querySelector`/`querySelectorAll`, создание и замена узлов через `createElement`/`replaceChildren`, безопасный вывод текста через `textContent`, делегирование событий через `addEventListener` на контейнере, поиск целевой кнопки через `closest` и чтение `data-*` с числовой проверкой.

Ключевое различие — **изменение данных и изменение DOM**. Удаление `<li>` само по себе не удаляет задачу: после повторной отрисовки она появится снова, пока массив не изменён. Поэтому каждая успешная операция сначала проходит через функцию ПР2 и только потом вызывает `renderApp`.

Наиболее показательной ошибкой была бы попытка читать `dataset.action` непосредственно у `event.target`. При клике по вложенному `span.action-label` атрибут находится у кнопки-родителя, а не у `span`. Решение — `event.target.closest("button[data-action]")`.

Вторая ошибка — присваивание видимой выборки в `currentTasks`. После такого присваивания фильтр «Все» уже не может вернуть скрытые записи. Правильная модель — два независимых значения: полный массив `currentTasks` и режим `currentFilter`, а видимая выборка рассчитывается на каждом рендере.
